## **Что такое Streamlit.**

> **Streamlit** – библиотека Python, которая превращает скрипт в веб-страницу.

Вы пишете файл `.py` с вызовами `st.что-то`. Каждый вызов добавляет на страницу элемент: заголовок, таблицу, ползунок.

Приложение состоит из трёх частей:

1. **Скрипт** – ваш файл `.py`.
2. **Сервер** – процесс Python, который запускает команда `streamlit run`. Он выполняет скрипт и собирает из него страницу.
3. **Браузер** – показывает страницу и сообщает серверу о каждом действии пользователя.

Как они работают вместе:

1. Браузер открыл адрес.
2. Сервер выполнил скрипт сверху вниз.
3. Браузер нарисовал результат.
4. Пользователь что-то нажал – сервер снова выполнил скрипт.

Главное отличие от ноутбука: ячеек нет. Файл всегда выполняется целиком, и запускает его сервер, а не вы.

## **Секрет за паролем.**

Окружение готово, пора запускать. Первое приложение показывает секрет только тому, кто знает пароль.

Кода в нём несколько строк. Зато на нём видно главное: как Streamlit выполняет скрипт.

### **Первый запуск.**

Создайте файл `mini/00_secret.py`:

```python
import streamlit as st  # принято сокращать до st

st.title("Секрет за паролем")  # самый крупный заголовок страницы
st.write("Введите пароль, чтобы увидеть секрет.")  # обычный текст
```

Полный файл – `mini/00_secret.py`.

Запускают его не через `python`, а через Streamlit:

```bash
streamlit run mini/00_secret.py --server.runOnSave true
# run                     – поднять сервер и выполнить файл
# --server.runOnSave true – выполнять файл заново при каждом сохранении
```

В терминале появятся адреса:

```text
You can now view your Streamlit app in your browser.

Local URL: http://localhost:8501
Network URL: http://192.168.1.37:8501
```

> **localhost** – имя вашего же компьютера.

> **Порт** – номер, по которому браузер находит нужную программу на компьютере. Streamlit по умолчанию занимает порт `8501`.

Браузер откроет страницу сам. Если нет – скопируйте `Local URL` в адресную строку.

**Полезно знать:**

- при самом первом запуске Streamlit спросит email – просто нажмите Enter;
- `Network URL` – адрес для других устройств в вашем Wi-Fi, например для телефона;
- пока сервер работает, терминал занят им; остановить сервер – `Ctrl+C`;
- другие команды набирайте во втором окне терминала, активировав там окружение.



### **Порядок на странице.**

Поменяйте местами строки с `st.title` и `st.write` и сохраните файл.

Страница обновилась сама: это сделал флаг `--server.runOnSave true`. Без него Streamlit покажет справа вверху кнопку `Rerun`.

Текст теперь над заголовком. **Порядок вызовов в файле – порядок элементов на странице.**

Текстовых команд несколько, отличаются они видом:


| Команда                                    | Что рисует                                        |
| ------------------------------------------ | ------------------------------------------------- |
| `st.title("...")`                          | заголовок страницы, самый крупный                 |
| `st.header("...")` / `st.subheader("...")` | заголовок раздела и подраздела                    |
| `st.markdown("**жирный** текст")`          | текст с разметкой Markdown, как в ячейке ноутбука |
| `st.caption("...")`                        | мелкая серая подпись                              |
| `st.write(...)`                            | что угодно: строку, число, список, таблицу        |




### **Поле для пароля.**

Пароль нужно куда-то ввести. В полном файле поле уже есть:

```python
password = st.text_input("Пароль", type="password")  # вместо символов – точки
```

Полный файл – `mini/00_secret.py`.

> **Виджет** – элемент страницы, через который пользователь передаёт значение: поле, список, ползунок, флажок, кнопка.

В коде виджет – вызов функции. Он делает две вещи: рисует элемент **и возвращает его текущее значение**.

Пока поле пустое, `password` – пустая строка `""`. `type="password"` прячет символы точками: возвращает поле то же самое, изменился только вид.

Наберите `abc` и нажмите Enter. Мы не писали «при изменении поля обнови текст». Как это сработало?

> **Перезапуск (rerun)** – Streamlit выполняет **весь** файл заново, с первой строки до последней.

Перезапуск происходит при каждом действии пользователя: ввёл текст, сдвинул ползунок, нажал кнопку.

Вы нажали Enter, и сервер выполнил файл с начала. В этот раз `st.text_input` вернул `"abc"`.

### **Проверка пароля.**

Осталось сравнить введённое с правильным паролем. Внизу покажем время выполнения файла: так перезапуск будет видно глазами.

```python
if password == "":
    st.info("Введите пароль и нажмите Enter.")
elif password == PASSWORD:
    st.success("Пароль верный.")
    st.write("Секрет: СЕКРЕТ ХАХА.")
else:
    st.error("Пароль неверный")

st.caption(f"Скрипт выполнен в {time.strftime('%H:%M:%S')}")
```

Полный файл – `mini/00_secret.py`.

Проверьте три случая:

1. Поле пустое – синяя подсказка «Введите пароль и нажмите Enter.».
2. `qwerty` – красное «Пароль неверный».
3. `streamlit` – зелёное «Пароль верный.» и секрет.

Каждый раз время внизу новое: файл выполнился целиком.

Теперь нажмите `R` на клавиатуре. Это перезапуск без действия пользователя. Время сменилось, а секрет остался: поле помнит набранное.

Пустую строку проверяем первой. Иначе человек, только открывший страницу, сразу увидел бы «Пароль неверный».

Цветных блоков четыре:


| Команда             | Когда                                 |
| ------------------- | ------------------------------------- |
| `st.info("...")`    | подсказка: что сделать дальше         |
| `st.success("...")` | всё получилось                        |
| `st.warning("...")` | работать можно, но результат странный |
| `st.error("...")`   | дальше нельзя                         |


Пароль прямо в коде попадёт на GitHub вместе с кодом. Как хранить его правильно, разберём в разделе про деплой.

## **Конвертер длины.**

Перезапуск понятен на тексте. Но модели нужны числа и выбор из вариантов. Второе приложение переводит длину между метрами, футами и дюймами.

### **Поле для числа.**

> `st.number_input("Подпись")` – поле для числа с кнопками плюс и минус. Возвращает число, которое в нём стоит.

Начнём с одного направления: метры в футы. В одном футе ровно `0.3048` метра.

```python
meters = st.number_input("Метры", min_value=0.0, value=1.0, step=0.5)
# min_value – меньше ввести нельзя: длина не бывает отрицательной
feet = meters / 0.3048  # в одном футе ровно 0.3048 метра

st.success(f"{meters:.2f} м = {feet:.2f} фт")
```

Полный файл – `mini/01_length.py`.

```bash
# Ctrl+C в терминале с сервером, затем
streamlit run mini/01_length.py --server.runOnSave true
```

На странице:

```text
1.00 м = 3.28 фт
```

Параметры поля:

- `min_value` – нижняя граница;
- `value` – значение при открытии;
- `step` – шаг кнопок плюс и минус.

`:.2f` в f-строке – два знака после точки. Без него на странице было бы `3.280839895013123`.

**Ловушка: числа в параметрах должны быть одного типа.**

- `min_value=0, value=1.0` – целое и дробное вместе – даёт ошибку `StreamlitMixedNumericTypesError: All numerical arguments must be of the same type`.
- Тип результата определяется ими же: если все числа целые, поле вернёт `int`.
- Длина бывает дробной, поэтому все числа пишем с точкой.



### **Три единицы.**

Одно направление – мало. Пусть единицы выбирают из списка.

> `st.selectbox("Подпись", варианты)` – выпадающий список. Возвращает выбранный вариант, по умолчанию первый.

Пар «из чего во что» шесть, но шесть формул не нужно. Для каждой единицы запишем, сколько в ней метров. Любой перевод – два шага:

1. Перевести в метры: умножить на множитель исходной единицы.
2. Перевести из метров: разделить на множитель нужной единицы.

Новая единица – одна строка в словаре, например `"см": 0.01`.

```python
METERS_IN = {"м": 1.0, "фт": 0.3048, "дюйм": 0.0254}  # сколько метров в одной единице

value = st.number_input("Длина", min_value=0.0, value=1.0, step=1.0)
unit_from = st.selectbox("Из", list(METERS_IN))  # list(словарь) – список его ключей
unit_to = st.selectbox("В", list(METERS_IN), index=1)  # index=1 – по умолчанию второй вариант

meters = value * METERS_IN[unit_from]  # сначала в метры
result = meters / METERS_IN[unit_to]  # потом из метров в нужную единицу
```

Полный файл – `mini/02_length_units.py`.

`st.selectbox` вернул строку, например `"фт"`. По ней берём множитель из словаря.

Ноль – не ошибка, но переводить нечего. Поэтому `st.warning`, а не `st.error`.

Попробуйте:


| Ввели | Из    | В     | Результат                    |
| ----- | ----- | ----- | ---------------------------- |
| `1`   | м     | фт    | `1.00 м = 3.28 фт`           |
| `1`   | м     | дюйм  | `1.00 м = 39.37 дюйм`        |
| `1`   | фт    | дюйм  | `1.00 фт = 12.00 дюйм`       |
| `6`   | фт    | м     | `6.00 фт = 1.83 м`           |
| `100` | дюйм  | м     | `100.00 дюйм = 2.54 м`       |
| `0`   | любая | любая | «Введите длину больше нуля.» |


Ещё один довод за `:.2f`. Без формата фут в дюймах – `12.000000000000002`. Дробные числа в компьютере хранятся приближённо.

### **Колонки.**

Число и две единицы – части одного вопроса. Удобнее видеть их в одной строке.

> `st.columns(3)` – три колонки рядом. Возвращает три контейнера, по одному на колонку.

```python
left, middle, right = st.columns(3)  # три колонки рядом; каждая – свой контейнер
value = left.number_input("Длина", min_value=0.0, value=1.0, step=1.0)
unit_from = middle.selectbox("Из", list(METERS_IN))
unit_to = right.selectbox("В", list(METERS_IN), index=1)
```

Полный файл – `mini/03_length_columns.py`.

`left.number_input(...)` – тот же `st.number_input`, только в левой колонке.

Если элементов в колонке несколько, удобнее блок `with left:`. Всё внутри блока пойдёт в эту колонку.

На телефоне колонки встают друг под другом. Streamlit перестраивает их сам.

**Полезно знать:** подпись поля можно спрятать, но не стирать. С пустой подписью `""` Streamlit пишет в терминал предупреждение «`label` got an empty value». Правильно – оставить подпись и передать `label_visibility="collapsed"`.

## **Как Streamlit устроен внутри.**

Два приложения работают, и перезапуск мы видели руками. Перед следующим приложением разберём, что за перезапуском стоит. Почти каждая ловушка дальше – следствие одного из шагов ниже.

### **Шаг 1. Сервер.**

`streamlit run` запускает процесс Python, а в нём – веб-сервер на порту `8501`.

> **Веб-сервер** – программа, которая ждёт запросов на порту и отвечает на них: отдаёт страницу, файл, данные.

С версии 1.57 (апрель 2026) это **Uvicorn** с приложением на **Starlette**. Раньше здесь был **Tornado**, и в старых статьях он ещё встречается. Для нас разницы нет.

### **Шаг 2. Страница-оболочка.**

Браузер открыл адрес. Сервер отдал ему готовый фронтенд на JavaScript.

Этот фронтенд собран заранее и лежит внутри пакета, в папке `streamlit/static`. Ваш Python HTML не пишет. Оболочка одна для всех приложений и ждёт, что сервер скажет, что рисовать.

### **Шаг 3. Постоянное соединение.**

Оболочка открывает к серверу соединение по адресу `/_stcore/stream`.

> **WebSocket** – соединение, которое остаётся открытым. Обе стороны шлют по нему сообщения когда угодно, пока вкладка открыта.

Обычный запрос устроен иначе: спросил, получил ответ, разошлись.

> **Сессия** – всё, что сервер помнит про одно соединение. Одна вкладка браузера – одна сессия.

Отсюда:

- две вкладки с одним приложением – две сессии, даже у одного человека;
- обновили страницу (`F5`) – новая сессия, с нуля.



### **Шаг 4. Выполнение скрипта.**

Для сессии сервер запускает ваш файл. Делает это **ScriptRunner** в **отдельном потоке**, у каждой сессии свой. Сервер в это время свободен и обслуживает других.

> **Поток** – отдельная линия выполнения внутри процесса. Потоки работают одновременно и видят общую память процесса.

Скрипт выполняется на сервере, а не в браузере. Поэтому у него нет доступа к файлам на компьютере пользователя. Есть только то, что пользователь сам загрузит через страницу.

И поэтому `python mini/00_secret.py` страницы не даст. ScriptRunner не запущен, и каждый вызов `st.*` пишет в терминал `missing ScriptRunContext`: «не знаю, какой сессии я принадлежу».

### **Шаг 5. Элементы едут по частям.**

`st.title(...)` сам ничего не рисует. Он упаковывает элемент в сообщение и отправляет в браузер по WebSocket. Рисует оболочка.

Следующая строка скрипта – следующее сообщение. Поэтому страница появляется **по мере выполнения** скрипта. Если перед таблицей идёт долгий расчёт, заголовок уже на экране, а таблицы ещё нет.

> **Protobuf** – компактный двоичный формат сообщений. В нём Streamlit и шлёт элементы страницы.



### **Шаг 6. Пользователь что-то нажал.**

1. Оболочка отправляет серверу новые значения виджетов.
2. Сервер записывает их в **эту** сессию.
3. ScriptRunner выполняет файл с первой строки.
4. Пока прогон идёт, старые элементы бледнеют. Новые заменяют их по одному.

Пользователь нажал ещё раз, пока прогон не закончился? Прошлый прогон обрывается, и начинается новый.

Обрыв срабатывает на ближайшем вызове `st.*`. Значит, долгий расчёт **без** `st.`* посередине прервать нельзя. Если `model.fit` идёт минуту, новый клик подождёт.

### **Шаг 7. Вы сохранили файл.**

Сервер следит за файлом скрипта и за вашими модулями, которые тот импортирует. Файл поменялся – с `--server.runOnSave true` перезапуск происходит сразу.

**Полезно знать:** совет `For better performance, install the Watchdog module` при запуске на macOS – не ошибка. С пакетом `watchdog` изменения файлов видны быстрее.

### **Где что живёт.**

Из шагов следует главное: у данных три места жизни.


| Где                   | Что там                                 | Сколько живёт                        |
| --------------------- | --------------------------------------- | ------------------------------------ |
| прогон скрипта        | обычные переменные, например `password` | один прогон                          |
| сессия (одна вкладка) | значения виджетов и память сессии       | пока вкладка открыта                 |
| процесс сервера       | кэш                                     | пока сервер работает; общий для всех |


Первую строку мы уже видели: `password` и `meters` каждый раз получаются заново. Вторая строка – генератор паролей. Третья – раздел про кэш.

### **Настройки сервера.**

`--server.runOnSave true` – одна из настроек сервера. Задать настройку можно двумя способами.

Флагом – на один запуск:

```bash
streamlit run mini/00_secret.py --server.port 8502
# --server.port – настройка port из раздела server
# получается: Local URL: http://localhost:8502
```

Файлом `.streamlit/config.toml` – навсегда. Папка `.streamlit` лежит там, откуда запускаете `streamlit run`, то есть в `ml-streamlit`:

```toml
[server]
runOnSave = true
# то же, что флаг --server.runOnSave true, только навсегда
```

Имя одно и то же: `server.runOnSave` – это `runOnSave` в разделе `[server]`.

**Полезно знать:**

- второй `streamlit run` при работающем первом сам возьмёт следующий порт, `8502`;
- порт, заданный явно, Streamlit не подменяет: занят – сервер остановится с `Port 8502 is not available`;
- все настройки с пояснениями печатает `streamlit config show`.

## **Генератор паролей.**

Мы знаем, что переменные живут один прогон. Третье приложение показывает, когда это мешает. Оно собирает пароль из случайных символов, а главный герой здесь – кнопка.

### **Пароль из случайных символов.**

Наборы символов есть в стандартном модуле `string`, случайный выбор – в `random`.

```python
symbols = string.ascii_letters + string.digits + string.punctuation
# буквы a–z и A–Z, цифры 0–9, знаки препинания – одной строкой
password = "".join(random.choices(symbols, k=16))  # склеить список символов в одну строку
st.code(password, language=None)  # моноширинный блок с кнопкой копирования
```

`random.choices` возвращает **список**. `"".join(...)` склеивает его в строку. `st.code` рисует моноширинный блок с кнопкой копирования; `language=None` – без подсветки синтаксиса.

> **Магия** – если в главном файле на отдельной строке стоит просто переменная, Streamlit сам передаёт её в `st.write`.

Привычка из ноутбука «написать `df`, чтобы посмотреть» здесь показывает таблицу пользователю.

Новый пароль пока появляется только по клавише `R`. Пользователь про `R` не знает.

### **Ползунок, флажок, кнопка.**


| Виджет                            | Что возвращает                                        |
| --------------------------------- | ----------------------------------------------------- |
| `st.slider("Подпись", 8, 64, 16)` | число из диапазона; здесь от 8 до 64, по умолчанию 16 |
| `st.checkbox("Подпись")`          | `True`, пока галочка стоит                            |
| `st.button("Подпись")`            | `True` только в перезапуске после нажатия             |


```python
length = st.slider("Длина", 8, 64, 16)  # от 8 до 64, по умолчанию 16
use_special = st.checkbox("Спецсимволы")  # True, пока галочка стоит

if st.button("Создать"):
    symbols = string.ascii_letters + string.digits
    if use_special:
        symbols += string.punctuation
    password = "".join(random.choices(symbols, k=length))
    st.code(password, language=None)  # моноширинный блок с кнопкой копирования
```

Полный файл – `mini/04_password.py`.

```bash
streamlit run mini/04_password.py --server.runOnSave true
```

Пока кнопку не нажали, она возвращает `False`, и пароля нет. Нажали – перезапуск, кнопка вернула `True`, пароль появился.

### **Кнопка возвращает** `True` **один раз.**

Нажмите «Создать», а потом сдвиньте ползунок. Пароль пропал.

Почему:

1. Сдвиг ползунка – новый перезапуск.
2. В нём кнопка снова вернула `False`.
3. Переменная `password` не спасает: она живёт один прогон.

Чтобы пароль держался, есть три способа. У каждого своя задача.

### **Вариант 1. Память сессии.**

**Задача:** пароль должен пережить перезапуск.

> `st.session_state` – словарь, который переживает перезапуски. Он свой у каждой сессии, то есть у каждой вкладки.

Кнопка теперь только **записывает** пароль. Показывает его отдельный `if`, который от кнопки не зависит.

```python
if "password" not in st.session_state:  # только в самом первом прогоне сессии
    st.session_state.password = None

if st.button("Создать"):
    st.session_state.password = make_password(length, use_special)

if st.session_state.password:
    st.code(st.session_state.password, language=None)
```

Полный файл – `mini/05_password_state.py`.

**На экране:** двигайте ползунок – пароль на месте. Во второй вкладке браузера пароля нет: своя сессия – свой словарь.

- Проверка `"password" not in st.session_state` заводит ключ один раз. Без неё `None` стирал бы пароль на каждом прогоне.
- `st.session_state.password` – то же, что `st.session_state["password"]`.

**Когда брать:** результат нужно помнить между кликами.

### **Вариант 2. Колбэк.**

**Задача:** пароль держится, но после смены длины снова нужно жать «Создать». Хочется, чтобы новый пароль появлялся сам, как только сдвинули ползунок.

> **Колбэк** – функция, которую Streamlit вызывает сам при действии пользователя. Колбэк выполняется **до** перезапуска скрипта.

Кнопки принимают колбэк в параметре `on_click`, остальные виджеты – в `on_change`.

```python
def generate():
    # Колбэк работает до перезапуска: свежие значения виджетов – в session_state по key
    st.session_state.password = make_password(
        st.session_state.length,
        st.session_state.use_special,
    )

st.slider("Длина", 8, 64, 16, key="length", on_change=generate)
st.checkbox("Спецсимволы", key="use_special", on_change=generate)
st.button("Создать", on_click=generate)
```

Полный файл – `mini/06_password_callback.py`.

Что происходит, когда сдвинули ползунок:

1. Браузер отправляет серверу новое значение.
2. Streamlit кладёт его в `st.session_state["length"]`: это имя задал `key="length"`.
3. Streamlit вызывает `generate()`.
4. Только потом файл выполняется сверху вниз.

На шаге 3 файла ещё нет в этом прогоне, переменной вроде `length` тоже нет. Свежее значение лежит только в `st.session_state` по `key`.

`on_click=generate` – без скобок: функцию вызовет Streamlit, а не мы.

**На экране:** сдвинули ползунок или поставили флажок – сразу появился пароль новой длины. Кнопка «Создать» тоже работает.

**Когда брать:** действие должно сработать в момент изменения виджета.

**Полезно знать:**

- аргументы колбэку можно передать через `args=(...)`, но они вычисляются, когда виджет рисуется, то есть со значениями прошлого прогона; значения виджетов – только по `key`;
- выводить что-то через `st.*` из колбэка не стоит: колбэк меняет состояние, а рисует скрипт.



### **Вариант 3. Форма.**

**Задача:** каждый сдвиг ползунка – перезапуск. Когда настроек много, удобнее заполнить всё и применить разом.

> `st.form` – контейнер, внутри которого виджеты **не** перезапускают скрипт.

Значения формы уходят на сервер разом, по кнопке `st.form_submit_button`. Тогда и происходит один перезапуск.

```python
with st.form("settings"):  # "settings" – ключ формы, у каждой формы свой
    length = st.slider("Длина", 8, 64, 16)
    use_special = st.checkbox("Спецсимволы")
    submitted = st.form_submit_button("Создать")

if submitted:
    st.code(make_password(length, use_special), language=None)
```

Полный файл – `mini/07_password_form.py`.

**На экране:** двигаете ползунок – ничего не происходит. Нажали «Создать» – один перезапуск, все значения сразу.

`st.form_submit_button` тоже возвращает `True` один раз. Но пароль держится, пока на странице нет виджетов **вне** формы: менять больше нечего.

**Две ловушки:**

- без `st.form_submit_button` форму нечем отправить;
- обычная `st.button` внутри формы – ошибка «`st.button()` can't be used in an `st.form()`».

**Когда брать:** несколько полей, считать – когда заполнены все.

### **Какой вариант брать.**


| Вариант                         | Когда                                                |
| ------------------------------- | ---------------------------------------------------- |
| просто `st.button`              | результат не нужен после следующего клика            |
| `st.session_state`              | результат нужно помнить: история, последний прогноз  |
| колбэк `on_click` / `on_change` | действие должно сработать в момент изменения виджета |
| `st.form`                       | несколько полей, считать – когда заполнены все       |


В приложении с моделью будет форма: пять полей и одна кнопка.

## **Графический калькулятор.**

Состояние держать умеем. Но пока приложения выводили только текст. Модели понадобятся картинки и много настроек сразу.

Четвёртое приложение рисует графики функций. Соберём его по шагам: каждая версия – отдельный файл и одна новая идея.

### **Шаг 1. Готовый график.**

Начнём с графика без единого виджета: синус от 0 до 10.

```python
x = np.linspace(0, 10, 200)  # 200 чисел от 0 до 10 с равным шагом
y = np.sin(x)

fig, ax = plt.subplots()  # fig – вся картинка, ax – оси внутри неё
ax.plot(x, y)
st.pyplot(fig)  # вместо plt.show(): отправить картинку на страницу
```

Полный файл – `mini/08_plot_sin.py`.

```bash
streamlit run mini/08_plot_sin.py --server.runOnSave true
```

Всё как в ноутбуке, кроме последней строки.

> `st.pyplot(fig)` – показать на странице готовую фигуру matplotlib.



### **Шаг 2. Выбор функции.**

Пусть функцию выбирают из списка. `st.selectbox` уже знаком по конвертеру.

```python
function = st.selectbox("Функция", ["sin", "cos", "exp", "sqrt"])

x = np.linspace(0, 10, 200)
y = getattr(np, function)(x)  # getattr(np, "sin") – то же, что np.sin
```

Полный файл – `mini/09_plot_select.py`.

`st.selectbox` вернул **строку**, например `"sin"`. А посчитать нужно функцию.

- `getattr(np, "sin")` достаёт из модуля `np` то, что лежит под именем `"sin"`, – саму функцию `np.sin`.
- Вторые скобки её вызывают: `getattr(np, "sin")(x)` – то же, что `np.sin(x)`.

Без `getattr` пришлось бы писать `if / elif` на каждую функцию.

### **Шаг 3. Диапазон и подписи.**

Диапазон зашит в коде: от 0 до 10. Отдадим его пользователю и подпишем оси.

> `st.slider("Подпись", от, до, (левая, правая))` – если значение по умолчанию кортеж из двух чисел, у ползунка две ручки. Возвращает он тоже кортеж.

```python
x_min, x_max = st.slider("Диапазон x", -10.0, 10.0, (0.0, 10.0))
# value – кортеж из двух чисел: у ползунка две ручки, и вернёт он тоже кортеж

if x_min == x_max:
    st.error("Раздвиньте ручки: диапазон пустой.")
    st.stop()  # дальше строить нечего: этот прогон заканчивается здесь
```

Полный файл – `mini/10_plot_range.py`.

> `st.stop()` – закончить перезапуск на этой строке. Всё, что ниже, в этот раз не выполняется.

Приём пригодится везде, где дальше работать нечем: неверный ввод, нет файла, нет модели.

Подписи – обычный matplotlib, они уже в том же файле:

```python
ax.plot(x, y, label=f"{function}(x)")  # label – подпись линии для легенды
ax.set_title(f"График {function}(x)")
ax.set_xlabel("x")
ax.set_ylabel("y")
ax.legend()
```

Полный файл – `mini/10_plot_range.py`.

Выберите `sqrt` и сдвиньте левую ручку на -10: левая половина графика пустая. Корень из отрицательного числа numpy считает как `nan`, «не число», и matplotlib такие точки пропускает. В терминале появится `RuntimeWarning`.

**Полезно знать:** два виджета одного типа с одинаковыми параметрами – ошибка `StreamlitDuplicateElementId`. Снимают её разные подписи или разные `key`.

### **Шаг 4. Несколько функций и боковая панель.**

Сравнить две функции на одном графике пока нельзя. Нужен выбор нескольких вариантов сразу.

> `st.multiselect("Подпись", варианты, default=[...])` – список, где можно выбрать несколько вариантов. Возвращает **список** выбранных.

Настройки уберём на боковую панель, чтобы график был на виду.

> `st.sidebar` – панель слева. Всё, что вызвано внутри `with st.sidebar:`, рисуется там.

```python
with st.sidebar:
    functions = st.multiselect("Функции", ["sin", "cos", "exp", "sqrt"], default=["sin", "cos"])
    x_min, x_max = st.slider("Диапазон x", -10.0, 10.0, (0.0, 10.0))
    show_grid = st.checkbox("Сетка", value=True)
```

Полный файл – `mini/11_plot_multi.py`.

`functions` – список, поэтому линии рисуем в цикле. Пустой список – подсказка и `st.stop()`, как с пустым диапазоном.

Добавьте к `sin` функцию `exp`. Синус превратился в прямую у нуля: `exp(10)` больше двадцати тысяч, а масштаб у осей общий.

**Полезно знать:** у Streamlit есть и свои графики – `st.line_chart`, `st.bar_chart`, `st.scatter_chart`. Они интерактивные: подсказка со значением при наведении. Matplotlib берут, когда нужна точная настройка или график уже написан в ноутбуке.

### **Шаг 5. Своя формула.**

Четыре функции из списка – мало. Хочется вписать формулу самому, например `sin(x) * x`.

Для строки есть `st.text_input`, он знаком по секрету. Выполнить строку как выражение Python умеет встроенная функция `eval`.

```python
formula = st.text_input("y =", value="sin(x) * x")
# ...
try:
    # Только для своего компьютера: eval выполнит любой код, который ввели в поле
    y = eval(formula, vars(np) | {"x": x})
except Exception as error:
    st.error(f"Не получилось посчитать формулу: {error}")
    st.stop()
```

Полный файл – `mini/12_plot_formula.py`.

Как работает строка с `eval`:

- `eval(строка, имена)` выполняет строку, а имена для неё берёт из словаря;
- `vars(np)` – словарь всех имён numpy: `sin`, `cos`, `pi` и других;
- `|` добавляет к нему `{"x": x}`;
- поэтому в формуле пишут `sin(x)`, без `np.`.

Формула с ошибкой, например `sin(`, падает внутри `eval`. `try / except` показывает текст ошибки, и `st.stop()` не даёт дойти до графика.

> **Важно.** `eval` выполняет **любой** код Python, не только формулы: прочитать файлы, удалить их, отправить секреты.
>
> Скрипт выполняется на сервере (шаг 4 устройства). Значит, и код из поля выполнится на сервере.
>
> - На своём ноутбуке это игрушка.
> - В интернете это терминал вашего сервера для каждого, кто открыл ссылку.
>
> Для чужих формул оставляют фиксированный список функций, как на шаге 4. Обёртки вроде `sympy.sympify` внутри тоже вызывают `eval` и не защищают.

Правило на всю пару: всё, что пришло от пользователя, – данные, а не код.

## **Кэш.**

Графики считались мгновенно. С моделью будет иначе: она читается с диска, и перезапуск делал бы это на каждом клике.

Чтобы не повторять долгую работу, в Streamlit есть кэш. Подключается он декоратором.

> **Декоратор** – строка `@имя` над `def`. Она оборачивает функцию: каждый вызов сначала попадает в обёртку, и обёртка решает, выполнять ли тело.

Сегодня декораторы только используем, писать свои не будем.

```python
@st.cache_data
def slow_square(number):
    time.sleep(3)  # притворяемся тяжёлым расчётом
    return number * number


number = st.slider("Число", 1, 10, 5)
st.write("Квадрат:", slow_square(number))
```

Полный файл – `mini/13_cache.py`.

Двигайте ползунок:

- каждое **новое** число ждёт три секунды;
- число, которое уже было, – мгновенно.

> `@st.cache_data` – кэш по коду функции и значениям аргументов. Такой вызов уже был – возвращается сохранённый результат, тело не выполняется.

Это третья строка таблицы «Где что живёт». Кэш лежит в процессе сервера и общий для всех:

- первый посетитель ждёт, второй с тем же числом – нет;
- кэш пропадает, когда сервер остановили или поменяли код функции;
- очистить вручную – клавиша `C` на странице.

Каждый вызов получает **копию** результата. Так один пользователь не испортит результат остальным. Для модели копия не подходит, и для неё есть второй декоратор, `@st.cache_resource`. Разберём его вместе с моделью.

## **Свой HTML.**

Встроенных элементов обычно хватает. Но иногда нужен свой вид, например карточка с вероятностью ухода клиента. Тогда Streamlit разрешает вставить HTML.

```python
st.markdown("По умолчанию теги показываются как текст: <b>не жирный</b>")
st.markdown("А так рисуются: <b style='color: crimson'>жирный красный</b>", unsafe_allow_html=True)
```

Полный файл – `mini/14_html.py`.

Способа два:

- `st.markdown(..., unsafe_allow_html=True)` – один-два тега внутри текста. Без этого флага теги видны как текст.
- `st.html(...)` – HTML целиком. Перед вставкой Streamlit чистит его библиотекой DOMPurify. JavaScript выполняется только с явным `unsafe_allow_javascript=True`.

В старых статьях встречается `streamlit.components.v1.html`. С версии 1.56 он устарел, вместо него – `st.html`.

Последние две строки файла – о безопасности. В поле стоит `<i>Гость</i>`, а на странице видны сами теги, а не курсив:

```python
name = st.text_input("Имя", value="<i>Гость</i>")
st.html(f"<p>Привет, {html.escape(name)}!</p>")  # escape – теги из ввода станут текстом
```

Полный файл – `mini/14_html.py`.

`html.escape` превратил `<` и `>` в безопасные `<` и `>`.

> **Важно.** Чужое – ввод пользователя, загруженный файл, ответ языковой модели – в HTML вставляют только через `html.escape`.
>
> Иначе на страницу попадёт чужая разметка. А с `unsafe_allow_javascript=True` – чужой код, который выполнится в браузере каждого посетителя.

Документация Streamlit советует HTML в последнюю очередь. Свой HTML не подстраивается под тёмную тему и может сломаться при обновлении библиотеки.

## **Как сохранить модель.**

В приложении модель не переобучают на каждый запрос. Её один раз сохраняют в файл, а страница восстанавливает её без повторного обучения.

> **Сериализация** – превратить объект Python в поток байтов, чтобы положить в файл и потом восстановить.



### `pickle`**: две функции.**

`pickle` – стандартный модуль Python для сериализации. Две функции:

1. `pickle.dump(obj, file)` – сериализует объект и записывает в файл;
2. `pickle.load(file)` – читает файл и восстанавливает объект.

Файл открывают в бинарном режиме: `"wb"` для записи, `"rb"` для чтения. `protocol=pickle.HIGHEST_PROTOCOL` – самая новая версия формата.

Для любой модели `scikit-learn` строки одни и те же. Например, `LinearRegression`:

```python
import pickle

with open("linear_model.pkl", "wb") as f:  # wb – запись в бинарном режиме
    pickle.dump(model, f, protocol=pickle.HIGHEST_PROTOCOL)

with open("linear_model.pkl", "rb") as f:  # rb – чтение в бинарном режиме
    loaded_model = pickle.load(f)

prediction = loaded_model.predict(X_new)  # X_new – новые данные с теми же колонками
```



### **Что попадает в файл, а что нет.**

Файл хранит **состояние объекта**: обученные веса, параметры, вложенные объекты. Кода классов и функций в нём нет, только их имена. Отсюда три правила:

1. **Подготовка данных – внутри** `Pipeline`**.** Всё, что делали с данными перед `fit`, сохранится в том же файле. У нас это перевод `Yes` / `No` и средние `StandardScaler`. Иначе приложение должно повторить те же преобразования вручную – и рано или поздно они разойдутся с обучением.
2. **Версии закреплены.** Класс при загрузке берётся из установленной библиотеки. Другая версия `scikit-learn` может файл не загрузить или выдать `InconsistentVersionWarning`. Поэтому в `requirements.txt` стоит `==`.
3. **Внутри модели нет своих функций и лямбд.** Функция из ноутбука сохраняется как имя `__main__.имя`. В приложении такого имени нет, и загрузка падает с `AttributeError`. Поэтому в нашем `Pipeline` только готовые классы `scikit-learn`.



### **Безопасность.**

> **Важно.** Никогда не загружайте pickle-файлы из ненадёжных источников.

Файл хранит инструкцию «как собрать объект», а она может вызвать любую функцию. Значит, при загрузке такой файл выполнит любой код.

По той же причине, что `eval` в калькуляторе: чужой файл модели – чужая программа на вашем сервере. Загружайте только свои файлы.

**Вопрос к аудитории:** почему в нашем приложении не будет кнопки «загрузите свою модель»?

**Ответ:** от пользователя приходят **данные**, а не модель.

### **Почему для** `scikit-learn` **берут** `joblib`**.**

Внутри `joblib` – тот же `pickle`, но рассчитан на большие массивы numpy, а из них и состоит обученная модель. Файл открывать не нужно:

```python
import joblib

joblib.dump(model, "linear_model.joblib")
loaded_model = joblib.load("linear_model.joblib")
```

Умеет сжимать: `joblib.dump(model, path, compress=3)`. Наш ноутбук сохраняет так.

### **Когда файл чужой:** `skops`**.**

`skops` – формат для моделей `scikit-learn`. При загрузке собирает только разрешённые типы. Незнакомые сначала показывает, а загрузить их можно, только перечислив явно:

```python
import skops.io as sio

sio.dump(model, "model.skops")
unknown = sio.get_untrusted_types(file="model.skops")  # какие типы внутри файла
loaded = sio.load("model.skops", trusted=unknown)  # загрузить можно, только перечислив их
```

Свой учебный файл так проверять не обязательно. `skops` нужен, когда модель приходит извне или вы её публикуете.

### **Когда прогноз нужен не на Python: ONNX.**

**ONNX** – модель как граф вычислений, без кода Python. Конвертер `skl2onnx`, запуск через `onnxruntime`; он есть не только для Python, но и для C++, C#, Java, JavaScript.

Ограничение: конвертируется не всё. Свои функции и редкие преобразования придётся описывать отдельно.

### **Родные форматы и MLflow.**

У бустингов есть свой `save_model`: XGBoost в JSON, CatBoost в `.cbm`. У PyTorch обычно сохраняют веса: `torch.save(model.state_dict(), path)`.

**MLflow** – не формат, а учёт: файл модели, версии пакетов, метрики и история версий в одном месте. К нему подойдём дальше в блоке MLOps.

### **Сравнение.**


| Способ        | Чужой файл безопасен            | Нужен Python          | Когда брать                                           |
| ------------- | ------------------------------- | --------------------- | ----------------------------------------------------- |
| `pickle`      | нет                             | да                    | любой объект Python, когда нет `joblib`               |
| `joblib`      | нет                             | да                    | модель `scikit-learn` в своём проекте                 |
| `cloudpickle` | нет                             | да                    | в объекте есть лямбды или функции из ноутбука         |
| `skops`       | да, только разрешённые типы     | да                    | модель `scikit-learn` из чужих рук или для публикации |
| ONNX          | да: внутри вычисления, а не код | нет                   | прогноз не на Python: сайт, телефон, другой язык      |
| родной формат | обычно да                       | зависит от библиотеки | бустинги, нейросети                                   |




### **Что выбрать на этой паре.**

- Модель `scikit-learn` в учебном проекте – `joblib` и закреплённые версии. Это наш случай.
- Файл модели приходит извне – `skops`.
- Прогноз нужен не на Python – ONNX.

Дальше ноутбук сохранит `model.joblib`. Приложение прочитает тот же файл.

## **Приложение с моделью.**

Модель лежит в `model.joblib`. Теперь – страница, которая её загружает и предсказывает.

### **Загрузить модель один раз.**

Помните раздел про кэш: на каждый клик файл выполняется заново. Строка `model = joblib.load(...)` без кэша читала бы модель с диска при каждом движении ползунка.

`@st.cache_data` здесь не подходит: он отдаёт каждому вызову **копию**, а копия модели – это снова сборка объекта из байтов.

> `@st.cache_resource` – кэш, который отдаёт **тот же самый** объект каждому вызову и каждому пользователю. Для моделей и подключений к базе.

```python
@st.cache_resource  # прочитать файл один раз на весь сервер, общий для всех сессий
def load_model():
    return joblib.load(MODEL_PATH)
```

Полный файл – `app.py`.


|                    | `@st.cache_data`       | `@st.cache_resource`     |
| ------------------ | ---------------------- | ------------------------ |
| что кэшируем       | таблица, строка, байты | модель, подключение к БД |
| что получает вызов | копию                  | тот же объект            |


Раз объект один на всех, его не меняют. `model.fit(...)` в приложении переобучил бы модель всем сразу. `predict_proba` модель не меняет.

Обратная сторона: кэш не знает, что файл на диске поменялся. Переобучили модель и сохранили новый `model.joblib` – приложение продолжит отвечать старой. Чтобы взять новую:

- остановите сервер (`Ctrl+C`) и запустите снова;
- или нажмите `C` на странице, или `Clear cache` в меню справа вверху;
- или в коде вызовите `st.cache_resource.clear()`.



### **Путь к файлу.**

```python
MODEL_PATH = Path(__file__).parent / "model.joblib"
# __file__ – путь к этому файлу; parent – его папка; / – склеить с именем файла
```

Полный файл – `app.py`.

Почему не просто `"model.joblib"`:

- такой путь Python ищет в папке, откуда запустили `streamlit run`, а не там, где лежит `app.py`;
- запустили из другой папки – `FileNotFoundError`, хотя файл на месте;
- облако запускает приложение из корня репозитория.

Нет файла – `st.stop()` в самом начале, как в калькуляторе.

### **Прогноз для одного клиента.**

Пять полей и одна кнопка – случай для формы, как в генераторе паролей. Порог «с какой вероятности считаем, что уйдёт» вынесем на боковую панель. Для одного элемента запись короче, чем `with st.sidebar:` – вызвать виджет прямо у панели: `st.sidebar.slider(...)`.

```python
threshold = st.sidebar.slider("Порог «уйдёт»", 0.05, 0.95, 0.5, step=0.05)

with st.form("client"):
    left, right = st.columns(2)
    with left:
        accountlength = st.number_input("Срок обслуживания", min_value=1, max_value=250, value=100)
        totaldayminutes = st.slider("Минут разговоров днём", 0.0, 400.0, 180.0, step=1.0)
        customerservicecalls = st.number_input("Звонков в поддержку", min_value=0, max_value=10, value=1)
    with right:
        internationalplan = st.checkbox("Международный план")
        voicemailplan = st.checkbox("Голосовая почта")
    submitted = st.form_submit_button("Предсказать")
```

Полный файл – `app.py`.

```bash
# Ctrl+C в терминале с сервером, затем
streamlit run app.py --server.runOnSave true
```

Модель ждёт таблицу. Поэтому клиент – таблица из одной строки: `pd.DataFrame([{...}])`, ключи словаря – колонки. Тариф пишем словами `Yes` / `No`, как в CSV: перевод в числа лежит внутри `Pipeline`.

```python
proba = model.predict_proba(client)[0, 1]
# строка 0 – наш единственный клиент; колонка 1 – вероятность класса 1, «ушёл»

st.metric("Вероятность ухода", f"{proba:.1%}")
st.progress(float(proba))
```

Полный файл – `app.py`.

> `st.metric(подпись, значение)` – одно число крупно, с подписью.

> `st.progress(доля)` – полоса, заполненная на долю от 0.0 до 1.0.

`float(...)` переводит число numpy в обычное число Python. `:.1%` печатает долю в процентах с одним знаком. `number_input` здесь целые, без точки: срок и звонки дробными не бывают.

Попробуйте:

- 4 звонка в поддержку и международный план, остальное по умолчанию – `75.7%`, «Скорее уйдёт»;
- без звонков и без плана – `4.9%`, «Скорее останется»;
- первый случай с порогом `0.8` – те же `75.7%`, но «Скорее останется».

Порог 0.5 – договорённость, а не закон. Кто хочет ловить больше уходящих, опускает порог и мирится с ложными тревогами.

Сдвиньте порог после прогноза – прогноз пропадёт. Ползунок стоит вне формы: его движение перезапускает файл, а кнопка формы снова `False`, как в генераторе паролей. Нажмите «Предсказать» ещё раз.

### **Прогноз по файлу.**

Клиентов по одному вводить долго. Допишем второй блок: загрузили CSV – получили его с вероятностями.

> `st.file_uploader(подпись, type="csv")` – поле, куда перетаскивают файл. Пока файла нет, возвращает `None`. Когда есть – объект, который `pd.read_csv` читает напрямую.

> `st.dataframe(таблица)` – интерактивная таблица: сортировка по клику, поиск.

> `st.download_button(подпись, data=..., file_name=...)` – кнопка, по которой браузер сохраняет файл.

```python
uploaded = st.file_uploader("CSV с клиентами", type="csv")  # пока файла нет – None
if uploaded is None:
    st.info("Загрузите CSV с теми же колонками, что ждут признаки модели.")
else:
    batch = pd.read_csv(uploaded)
    missing = [column for column in features if column not in batch.columns]
```

Полный файл – `app.py`.

`features` – `list(model.feature_names_in_)`, колонки, на которых модель училась. Чужой файл может быть любым: без проверки человек увидел бы трассировку вместо объяснения. Лишние колонки не мешают, если нужные на месте: мы передаём в модель только `batch[features]`.

`on_click="ignore"` у кнопки скачивания значит: файл сохранится, а скрипт заново не выполнится.

Проверьте на `clients.csv`:

1. Загрузите файл – в таблице 20 клиентов и две новые колонки.
2. При пороге 0.5 `True` в `churn_pred` нет: в этой случайной двадцатке уходящих модель не увидела.
3. Опустите порог до 0.3 – таблица пересчитается сама, `True` станет у одного.

## **Деплой.**

Приложение готово, но работает на `localhost`, то есть на **вашем** компьютере. Закрыли ноутбук – сервера нет.

Чтобы ссылку можно было отправить кому угодно, нужна машина, которая держит `streamlit run` всегда.

> **Деплой** – перенести приложение туда, где оно работает без вас и открывается по ссылке.

> **Streamlit Community Cloud** – бесплатная площадка для приложений Streamlit. Берёт код из репозитория на GitHub, ставит пакеты, запускает `streamlit run` и выдаёт ссылку вида `https://имя.streamlit.app`.

Схема из раздела про устройство та же, только сервер теперь на машине Streamlit. Окружение облако создаёт с нуля и видит только то, что лежит в репозитории.

### **Что поедет в облако.**

```text
ml-streamlit/
├── app.py             # приложение
├── model.joblib       # обученная модель
├── train_model.ipynb  # как модель получили; облако его не запускает
├── clients.csv        # 20 клиентов, чтобы проверить приложение
├── requirements.txt   # пакеты
├── .gitignore         # что не класть в репозиторий
└── mini/              # мини-приложения
```

Проект должен лежать в репозитории на GitHub.

- `model.joblib` кладём рядом с `app.py`: обучать модель облако не будет, а файл весит около 4 КБ.
- `mini/` можно оставить: облако запустит только тот файл, который вы назовёте.

Файл `.gitignore` рядом с `app.py` не даёт окружению `.venv/` и паролю из `secrets.toml` попасть в репозиторий:

```text
.venv/
.streamlit/secrets.toml
__pycache__/
.ipynb_checkpoints/
```



### **Зависимости.**

Облако ставит пакеты из того же `requirements.txt`, что вы ставили в начале пары.

### **Секреты.**

> **Секреты** – пароли и ключи. Локально их кладут в `.streamlit/secrets.toml`, а код читает через `st.secrets["имя"]`.

Самое время вернуться к первому приложению: там `PASSWORD = "streamlit"` записан прямо в `mini/00_secret.py`.

1. Создайте файл `.streamlit/secrets.toml` в папке `ml-streamlit`:

```toml
secret_password = "streamlit"
```

1. В `mini/00_secret.py` строку с паролем замените на:

```python
PASSWORD = st.secrets["secret_password"]  # пароль из .streamlit/secrets.toml, в коде его нет
```

Код можно выкладывать, пароль остаётся у вас.

**Полезно знать:**

- `st.secrets` ищет папку `.streamlit` там, откуда запустили `streamlit run`;
- нет файла – ошибка `No secrets found`;
- создали файл при работающем сервере – перезапустите сервер;
- в облаке секреты вставляют в `Advanced settings` → `Secrets`, а код читает их тем же `st.secrets`.



### **Community Cloud.**

1. Откройте [share.streamlit.io](https://share.streamlit.io) и войдите через GitHub.
2. Справа вверху `Create app`. На вопрос «Do you already have an app?» – `Yup, I have an app`.
3. **Repository** – ваш репозиторий, **Branch** – `main`, **Main file path** – `app.py`.
4. `Advanced settings`:
  - **Python version** – та же, что у вас локально: 3.14;
  - **Secrets** – содержимое `.streamlit/secrets.toml`. Модели пароль не нужен, он нужен секрету за паролем: тот же репозиторий, **Main file path** – `mini/00_secret.py`;
  - `Save`.
5. `Deploy`.

Через пару минут появится приложение, и ссылку можно отправить кому угодно.

> **Важно.** Версию Python выбирают **до** деплоя. Поменять её потом нельзя: только удалить приложение и задеплоить заново.



### **Обновление.**

Новый код из репозитория появляется в приложении сразу, новые пакеты из `requirements.txt` ставятся несколько минут.

**Полезно знать:**

- переобучили модель – положите новый `model.joblib` в репозиторий и нажмите `Reboot app` в `Manage app` справа внизу: иначе кэш продолжит отдавать старую модель;
- там же, в `Manage app`, – логи, если приложение упало;
- без посетителей 12 часов приложение засыпает; первый, кто откроет ссылку, нажмёт `Yes, get this app back up!`, и через минуту всё снова работает, а кэш начнётся с нуля.

Подробности – в документации: [Deploy your app on Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

### **Что ещё попробовать.**

Каждый пункт – одна функция и пара строк кода.

- `st.tabs(["А", "Б"])` – вкладки; например, «Один клиент» и «Файл» в приложении с моделью.
